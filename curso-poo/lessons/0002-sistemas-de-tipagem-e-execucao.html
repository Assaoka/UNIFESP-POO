TIPAGEM & EXECUÇÃO

Aula 2: Sistemas de Tipagem e Modos de Execução

Para acertar com tranquilidade as Questões 5 e 6 da prova, é indispensável separar dois conceitos que frequentemente são confundidos: quando a checagem de tipos ocorre (Estática vs Dinâmica) e o quanto o sistema de tipos tolera coerções implícitas (Forte vs Fraca).

1. O Eixo "Quando": Tipagem Estática vs Dinâmica

Linguagens Dinamicamente Tipadas: O tipo de uma variável é associado ao valor em tempo de execução (runtime). Uma variável pode receber um número e logo em seguida uma string sem restrições do compilador. Exemplos: Python, JavaScript, Ruby, PHP.

Linguagens Estaticamente Tipadas: Os tipos são verificados e garantidos em tempo de compilação (compile-time) antes da execução do programa. Erros de tipo são capturados cedo. Exemplos: Java, C, C++, TypeScript, Rust, Go.

2. O Eixo "Rigor": Tipagem Forte vs Fraca

Linguagens Fortemente Tipadas: Não realizam conversões implícitas mágicas entre tipos incompatíveis. Se você tentar somar uma string e um número, a linguagem interrompe a operação com erro de tipo (como `TypeError` em Python). Exemplos: Python, Java, Ruby, Haskell.

Linguagens Fracamente Tipadas: Permitem operações entre tipos díspares através de coerção automática implícita, gerando resultados muitas vezes surpreendentes ou bizarros. Exemplos: JavaScript, C, PHP, Perl.

A Matriz Canônica de Tipagem (Memorize para a Prova!)

Classificação Dinamicamente Tipada (Runtime) Estaticamente Tipada (Compile-time)
Fortemente Tipada
(Sem coerção implícita solta)		 Python, Ruby Java, Haskell, Rust, C#
Fracamente Tipada
(Coerção permissiva)		 JavaScript, PHP C, C++

3. O Eixo de Execução: Compilado vs Interpretado

Descreve como as instruções escritas pelo desenvolvedor são convertidas para código que a CPU entende:

  • Compiladas: O código-fonte passa por um compilador que gera código de máquina nativo ou bytecode (ex: C, C++, Go). A sobrecarga de tradução ocorre apenas uma vez antes da distribuição. Geralmente têm desempenho superior.
  • Interpretadas: O código é lido e executado por um programa interpretador sem necessidade de compilação prévia manual por parte do desenvolvedor (ex: Python com CPython, JavaScript com engine V8). A execução ocorre de forma direta/linha por linha.
  • Onde o TypeScript se encaixa? TypeScript adiciona tipagem estática em tempo de compilação ao ecossistema JavaScript. O compilador `tsc` realiza a análise e transpila o código para JavaScript puro, que depois é executado em runtime pelo Node.js ou navegador.

4. As Peculiaridades do JavaScript (Coerção de Tipos)

// JavaScript: Fracamente Tipado (Coerção implícita)
console.log(5 + "5");       // "55" (número vira string)
console.log("5" - 2);       // 3    (string vira número)
console.log(true + 1);      // 2    (true vira 1)
console.log(null + 1);      // 1    (null vira 0)
console.log(undefined + 1); // NaN  (undefined vira NaN)
console.log(typeof NaN);    // "number" (especificação IEEE 754)

// Python: Fortemente Tipado (Bloqueia coerção mágica)
# 5 + "5" -> TypeError: unsupported operand type(s) for +: 'int' and 'str'

// TypeScript: Captura erro já no editor e na compilação:
const total: number = 5 + "5"; // ❌ Type 'string' is not assignable to type 'number'
