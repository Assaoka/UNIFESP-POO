Aula 5: Polimorfismo, Classes Abstratas e Interfaces

O polimorfismo é frequentemente considerado o conceito mais poderoso da Programação Orientada a Objetos. Nesta aula, dissecamos a teoria, a herança com substituição em TypeScript e a distinção cirúrgica entre classes abstratas e interfaces. Este conteúdo resolve as Questões 7, 9 e 10 da prova.

1. O que é Polimorfismo?

A palavra tem origem no grego (poly = muitas, morphos = formas). Em POO:

Definição Canônica: Polimorfismo é a capacidade de diferentes classes implementarem métodos com o mesmo nome, mas comportamentos distintos, permitindo que objetos de diferentes subtipos sejam tratados de maneira uniforme por quem os consome.

O consumidor não precisa saber qual subclasse exata está sendo executada; ele apenas despacha a mensagem (chama o método) e o runtime invoca a implementação correspondente ao objeto concreto (Dynamic Dispatch).

2. Análise do Código da Questão 7: O Caso Animal, Cachorro, Gato e Dono

Veja como o polimorfismo por sobrescrita (method overriding) funciona na prática em TypeScript:

class Animal {
  fazerSom(): string {
    return "Algum som";
  }
}

class Cachorro extends Animal {
  override fazerSom(): string {
    return "Au au";
  }
}

class Gato extends Animal {
  override fazerSom(): string {
    return "Miau";
  }
}

class Dono {
  pet: Animal; // Referência polimórfica para a classe base!

  constructor(pet: Animal) {
    this.pet = pet;
  }

  fazerPetSoar(): string {
    // O Dono apenas invoca fazerSom().
    // O objeto real decidirá se late ou mia!
    return this.pet.fazerSom();
  }
}

// Execução da Questão 7:
const toto = new Gato();       // O pet criado é um GATO!
const dono = new Dono(toto);   // Passamos o gato para o Dono
console.log(dono.fazerPetSoar()); // SAÍDA: "Miau"

Por que imprime "Miau"?

Embora a propriedade pet esteja tipada na classe Dono como Animal, em tempo de execução a instância real referenciada na memória é do tipo Gato. O método fazerSom() invocado é o método sobrescrito de Gato, retornando "Miau".

3. A Diferença Crucial: Classes Abstratas vs Interfaces em TypeScript

Esta distinção é cobrada na íntegra na Questão 10 da prova. Domine cada detalhe:

Característica Classe Abstrata (abstract class) Interface (interface)
Implementação de Métodos Pode conter implementações completas (métodos concretos) além de métodos abstratos (apenas assinatura). Não pode conter implementação de métodos de execução em tempo de execução; define estritamente um contrato de tipos.
Existência em Runtime (JavaScript) Existe em runtime. Gera uma função construtora/classe real no código compilado `.js`. Desaparece totalmente após a compilação. É 100% apagada (type erasure), servindo apenas para análise estática de tipos do compilador.
Instanciação Direta (`new`) Não pode ser instanciada diretamente com new. Não pode ser instanciada diretamente com new (não existe em runtime).
Herança / Aplicação Uma classe estende apenas uma classe abstrata (extends). Uma classe pode implementar múltiplas interfaces (implements A, B, C). 
// 1. Exemplo de Interface em TypeScript
interface Autenticavel {
  login(senha: string): boolean; // Apenas contrato estático. Zero código em runtime!
}

// 2. Exemplo de Classe Abstrata
abstract class Funcionario {
  constructor(public nome: string, public salarioBase: number) {}

  // Método concreto compartilhado (reaproveitamento de código real)
  calcularBonusPadrao(): number {
    return this.salarioBase * 0.1;
  }

  // Método abstrato: filhas são OBRIGADAS a implementar
  abstract calcularSalarioLiquido(): number;
}
